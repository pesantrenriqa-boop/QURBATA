# Contributing to QURBATA

QURBATA is developed as a controlled educational and research project. Contributions must preserve scholarly integrity, pedagogical coherence, Qur’anic accuracy, and document traceability.

## Contribution Principles

1. Do not alter an approved Foundation rule indirectly through a lower-level document.
2. Every substantive change must explain its purpose and impact.
3. Arabic text, Qur’anic citations, hadith, transliteration, and translation must be checked against approved standards.
4. Pedagogical claims should be supported by evidence, testing, or a clearly stated rationale.
5. Superseded content must remain traceable through Git history or the archive.

## Document Status

Use one of these labels inside controlled documents:

- `DRAFT` — under active development
- `REVIEW` — ready for structured review
- `APPROVED` — authorized for use
- `SUPERSEDED` — replaced but retained for traceability
- `ARCHIVED` — preserved for historical reference

## File Naming

Foundation documents follow:

```text
F-001-Constitution.md
F-002-Lexicon.md
F-003-DNA.md
F-004-Graduate-Profile.md
F-005-Research-Protocol.md
```

Other controlled documents should use stable identifiers, descriptive names, and version metadata inside the file.

## Change Process

A proposed change should include:

- the problem being addressed;
- the governing document affected;
- the exact proposed revision;
- implications for curriculum, books, assessments, or research;
- verification or review required.

## Commit Messages

Use concise, action-based commit messages, for example:

- `Draft F-003 QURBATA DNA principles`
- `Clarify mastery criterion in F-001`
- `Add Jilid 1 phonetic progression standard`
- `Archive superseded assessment rubric`

## Approval

A commit records a change; it does not by itself make a document institutionally approved. Approval status must be stated within the controlled document and authorized through the project’s governance process.
